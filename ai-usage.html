使用的 AI 工具

AI 帮助完成的工作

2.1 需求拆解与设计

需求拆解

拿到"做一个个人介绍网站并部署到外网"这个需求后，先拆成可执行的任务链：

阶段任务产出验收标准
① 信息梳理整理个人简历、项目经历、技能清单结构化素材文档信息完整、无遗漏
② 结构设计确定页面分区和信息层级页面线框图 / 区块清单逻辑通顺、重点突出
③ 视觉选型确定风格基调、配色、字体视觉方案匹配技术人设
④ 开发实现HTML 骨架 → 样式 → 交互 → 图片可运行的网站桌面 / 移动端均正常
⑤ 部署上线推送 GitHub → 开启 Pages可访问的 URL外网能打开
⑥ 验证优化多端测试、性能排查、文案校对最终版本无 bug、加载正常

每个阶段有明确的产出和验收标准，做完一步再进下一步，避免 AI 一次性生成导致返工。

设计目标

做一个能同时体现「运维 + 开发」双背景的个人介绍网站，面向招聘方，3 秒内传达"我是谁、能做什么"，30 秒内看到项目实力。

信息架构设计

按「认知递进」原则排布页面分区，让访客从浅到深逐步了解我：

顺序区块设计意图核心信息
1Hero第一眼定位姓名 + 身份标签 + 一句话定位 + 联系方式
2About建立信任自我介绍 + 教育背景 + 荣誉证书
3Skills能力全貌6 类技能矩阵，覆盖运维 / 网络 / 嵌入式 / 开发 / 客户端 / AI
4Projects实力证明5 个真实项目，点击可查看详情
5Experience履历背书2 年校园 IT 运维，4 项职责
6Contact转化入口电话 / 邮箱 / GitHub

设计决策：联系方式在 Hero 和 Contact 出现两次——Hero 里让访客第一眼就能拿到，Contact 里作为最终转化入口。

视觉风格设计

  • •整体风格：深色科技风（纯黑底 + 中性灰文字 + 白色强调），匹配物联网 / 嵌入式 / 运维的技术人设，与 Moonshot / Vercel 等技术公司官网风格一致
  • •配色方案：背景 #000，正文 neutral-300/400，强调 white，点缀色用 emerald-400 表示"在线 / 可用"状态
  • •字体：Inter（英文 / 数字）+ Noto Sans SC（中文），兼顾现代感和中文可读性
  • •背景层次：网格线 + 径向渐变光晕 + 鼠标聚光灯 + Canvas 粒子，四层叠加营造空间深度

交互设计

  • •滚动进度条：顶部 2px 白线，实时反馈阅读进度
  • •AOS 入场动画：每个区块滚动到视口时淡入，引导阅读节奏
  • •项目弹窗：点击项目卡片弹出详情（多图 + 关键成果 + 技术标签），不跳页即可深读
  • •数字计数器：Hero 区"2 年运维""5+ 项目"从 0 滚动到目标值，强化记忆
  • •导航栏：滚动时毛玻璃化，固定顶部，移动端收为汉堡菜单

响应式策略

  • •断点：sm:640px（手机）、md:768px（平板）、lg:1024px（桌面）
  • •技能卡片：桌面 3 栏 → 平板 2 栏 → 手机 1 栏
  • •项目卡片：桌面图文左右分栏 → 移动端上下堆叠
  • •Hero 标题：桌面大号 → 移动端缩小，避免溢出
2.2 页面骨架与样式
  • •使用 Tailwind CSS 生成整体布局，采用深色科技风，匹配物联网 / 嵌入式 / 运维的技术人设
  • •生成响应式布局：桌面端三栏技能卡片、移动端单栏堆叠
  • •生成视觉细节：导航栏毛玻璃、网格背景、渐变光晕、滚动进度条
2.3 交互动画
  • •粒子背景动画（Canvas 实现）
  • •AOS 滚动入场动画
  • •项目详情弹窗（点击项目卡片弹出，含多图切换、关键成果列表）
  • •移动端汉堡菜单
  • •数字计数器动画
2.4 内容生成
  • •根据个人简历和项目经历，生成各区块文案
  • •技能标签分类：运维 & 部署、网络 & 硬件、嵌入式 & IoT、开发语言、客户端 & 工具、AI 辅助工具
  • •项目描述：智能快递分类系统、智能窗帘毕设、地图记忆、novel-server、OmniMedia Ops
2.5 部署
  • •生成 .gitignore、README
  • •指导 GitHub Pages 部署流程

自己手动修改的内容

AI 生成的代码不能直接用，以下是我手动介入的部分：

3.1 项目内容真实化

AI 初版生成的项目描述比较泛化，我根据自己真实经历重写了每个项目的描述：

  • ◦智能窗帘：补充了 STM32F103、ESP8266、OneNET MQTT、微信小程序的技术细节
  • ◦快递分类系统：明确了我的角色是功能测试和端到端联调
  • ◦OmniMedia Ops：补充了小红书真实图文预览、人工审核门禁等真实流程
3.2 图片资源处理
  • •手动整理项目截图，统一命名（curtain-hardware.jpg、express_sorting.jpg 等）
  • •调整图片尺寸和比例，确保在 16:10 卡片中不变形
  • •为地图记忆项目单独处理 Logo，使用居中展示而非满铺
3.3 移动端适配
  • •AI 生成的移动端字号偏大，手动调整 Hero 标题在手机端的尺寸
  • •项目卡片的图片和文字比例在窄屏下需要手动调 flex-col 切换
  • •联系方式按钮在手机端改为纵向堆叠
3.4 性能优化
  • •粒子背景在低端设备上卡顿，手动降低粒子数量和刷新频率
  • •项目弹窗图片懒加载，避免首屏加载所有大图
  • •AOS 动画在首屏加了兜底逻辑，防止 CDN 加载失败时内容不显示
3.5 文案校对
  • •修正 AI 生成的错别字和不通顺表述
  • •调整语气，让自我介绍更务实、不浮夸

遇到的问题及解决方式

问题 1：GitHub Pages 图片路径 404

  • 现象：本地预览正常，部署后部分图片显示裂图
  • 原因：AI 生成的路径用了绝对路径 /assets/xxx.jpg，GitHub Pages 子路径下需要相对路径 ./assets/xxx.jpg
  • 解决：全局替换图片路径，F12 Network 面板逐个验证

问题 2：AOS 动画首屏白屏

  • 现象：弱网环境下 AOS CDN 加载慢，首屏内容被 data-aos 隐藏导致白屏
  • 解决：加 <noscript> 兜底样式 + setTimeout 延迟兜底，确保 2 秒后无论 AOS 是否加载完成，内容都会显示

问题 3：移动端菜单点击无反应

  • 现象：汉堡菜单按钮在部分手机浏览器上点击无效
  • 原因：AI 写的事件监听用了 click，但某些移动浏览器有 300ms 延迟
  • 解决：改用 touchstart + click 双绑定，并加 e.preventDefault() 防止重复触发

问题 4：项目弹窗图片溢出

  • 现象：OmniMedia Ops 的 Dashboard 截图宽度超出弹窗
  • 解决：给图片加 max-w-full object-contain，并限制弹窗最大高度 max-h-[90vh] + overflow-y-auto

问题 5：Tailwind Play CDN 生产环境警告

  • 现象：控制台出现 "cdn.tailwindcss.com should not be used in production" 警告
  • 判断：对于个人作品集这种轻量场景，Play CDN 的体积和延迟可以接受，暂不迁移到构建流程；如果后续需要优化，可以改用 Tailwind CLI 预编译
